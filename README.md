# JARVIS CommerceOS

> **상품 후보를 찾고, 수익성을 확인한 뒤 판매 준비까지 한 흐름으로 관리하는 로컬 운영 대시보드**입니다.

CommerceOS는 개발 또는 개인 테스트 환경을 위한 도구입니다. 처음에는 AI API 키나 외부 판매 채널 계정을 연결하지 않아도 됩니다. 먼저 대시보드의 업무 흐름과 샘플 동작을 확인한 뒤, 필요한 연결만 추가하세요.

## 가장 먼저 할 일

필수 조건은 **Docker Desktop**입니다. Docker Desktop을 설치하고 실행한 뒤, 창이 완전히 켜진 것을 확인하세요. `start` 파일은 데이터베이스, API, 대시보드를 함께 시작하며, `.env`가 없는 경우에만 기본 설정 파일을 자동으로 만듭니다. **기존 데이터는 지우지 않습니다.**

| 운영체제 | 1단계 | 2단계 | 대시보드 |
| --- | --- | --- | --- |
| Windows | Docker Desktop을 실행합니다. | 프로젝트 폴더에서 `start.bat`를 더블클릭합니다. | `http://127.0.0.1:3000` |
| macOS / Linux | Docker Desktop 또는 Docker Engine을 실행합니다. | 터미널에서 `chmod +x start.sh && ./start.sh`를 실행합니다. | `http://127.0.0.1:3000` |

처음 실행할 때는 필요한 이미지를 준비하므로 시간이 조금 걸릴 수 있습니다. 실행 창에 서비스 로그가 계속 표시되는 동안은 정상입니다. 브라우저에서 `http://127.0.0.1:3000`을 열고, 실행 창은 대시보드를 사용하는 동안 닫지 마세요. 종료하려면 해당 창에서 `Ctrl+C`를 누릅니다.

## 로그인하고 첫 작업 시작하기

로컬 개발용 기본 계정은 아래와 같습니다. 이 계정은 **내 컴퓨터에서만 사용하는 초기 계정**이며, 외부에 서비스를 공개하거나 공유할 때는 반드시 비밀번호와 비밀 설정을 교체해야 합니다.

| 입력 항목 | 값 |
| --- | --- |
| 이메일 | `admin@jarvis.example.com` |
| 비밀번호 | `change-me-now` |

로그인한 뒤에는 다음 순서만 따르면 됩니다.

| 순서 | 메뉴 | 할 일 |
| --- | --- | --- |
| 1 | `상품 후보 찾기` | 판매해 볼 키워드를 입력하고 AI 분석 결과를 저장합니다. |
| 2 | `수익성 점검` | 후보의 마진, 예산, 손실 한도를 확인합니다. |
| 3 | `판매 준비` | 등록에 필요한 정보를 확인하고 승인 단계로 넘길 준비를 합니다. |

> 외부 판매 채널 등록, 재고·가격 변경처럼 중요한 작업은 사용자의 명시적 승인 전에는 실행되지 않습니다.

## 자주 막히는 경우

| 증상 | 먼저 해볼 일 |
| --- | --- |
| `Docker Desktop이 실행 중인지 확인하세요`가 보입니다. | Docker Desktop을 열고 엔진이 시작될 때까지 기다린 뒤 `start` 파일을 다시 실행하세요. |
| 브라우저에서 페이지가 열리지 않습니다. | 실행 창에서 오류가 없는지 확인하고, 서비스 준비가 끝난 뒤 `http://127.0.0.1:3000`을 다시 여세요. |
| `3000` 또는 `8001` 포트가 이미 사용 중이라고 나옵니다. | 이전에 실행한 CommerceOS 창에서 `Ctrl+C`로 종료한 뒤 다시 실행하세요. |
| 로그인되지 않습니다. | 기본 이메일과 비밀번호를 정확히 입력하고, 실행 창에서 API 오류가 없는지 확인하세요. |

| 주소 | 용도 |
| --- | --- |
| `http://127.0.0.1:3000` | 운영 대시보드 |
| `http://127.0.0.1:8001/docs` | API 문서 (개발자용) |
| `http://127.0.0.1:8001/health` | 서비스 상태 확인 |

> 기존 데이터를 완전히 삭제하고 처음부터 시작하는 작업은 별도 관리 절차입니다. 평소 실행 시에는 `docker compose down -v`를 사용하지 마세요. 자세한 설명은 [실행 가이드](docs/QUICKSTART.md)를 참고하세요.

## Render 스테이징 배포

루트의 `render.yaml`은 백엔드·프런트엔드·PostgreSQL 스테이징 환경을 Singapore 리전에 구성합니다. 비밀번호는 저장소에 기록하지 않고 Blueprint 생성 화면에서 입력합니다. 무료 PostgreSQL은 30일 후 만료되므로 운영 전환 전에 유료 플랜과 백업 정책을 확정해야 합니다. 자세한 절차는 [`docs/DEPLOY_RENDER.md`](docs/DEPLOY_RENDER.md)를 참조하세요.
